# Registers that are deliberately not offered

**Deutsch: [not-offered-registers.de.md](not-offered-registers.de.md)**

The Venus D, Venus A and Venus E v3 register maps were checked against the firmware of the control unit,
the inverter micro and the BMS. This page lists what the integration deliberately does **not** turn into
an entity or a button, and why. Every row comes from that analysis; the full per-register facts are in
the firmware analysis of the Venus D, A and E v3, and the register maps themselves are in
`custom_components/marstek_modbus/registers/`.

The registers that **are** offered as DEV buttons (45002, 45020, 45021, 45027, 45028, 45030; which
ones depends on the model) are not listed here: they need the option "Show DEV registers", are
disabled by default, and the ones that cannot be undone need a second press. The Wi-Fi credentials
have their own page: [set-wifi.md](set-wifi.md).

| Register(s) | What it does | Why it is not offered |
|---|---|---|
| 45000 | Puts the inverter micro into work mode 12 (factory mode, value `0x55EE`) or mode 1 (manual mode, value `0x55BB`) and sends it "off". | **High risk.** The output stops and the EMS set-points are ignored until the control unit restarts; the Control watchdogs are suspended. On the Venus A the PV input stage stops too and the BMS limits are replaced by fixed limits. |
| 45004, 45005, 45007, 45008 | Factory tests of the inverter micro: open-loop operation (45004), over-voltage test (45005), off-grid output test (45007), grid-tied power test at P watts (45008). They act only in work mode 12 (after 45000 = `0x55EE`); otherwise they are acknowledged and ignored. | **High risk.** Open-loop operation endangers the hardware, the off-grid test energises the backup output outside the normal sequence, and the power test bypasses every Control protection (SoC cut-off, backup reserve, limits). On the Venus A, 45005 does nothing in any mode. |
| 40000 | Starts the inverter micro's autonomous battery cycle test (charge and discharge). | **High risk.** It charges from and discharges into the grid with up to 2.5 kW on the Venus D (±1.35 kW on the Venus A) for hours, with the Control regulation bypassed. The derate flag stays set afterwards; on the Venus A the PV energy counters are erased too. |
| 45003, 45009, 45010 | Buzzer (45003), backup-output flag (45009), manual power set-point in watts (45010). They act only in work mode 1 or 12 (45003: mode 12 only, and it is acknowledge-only on the Venus A). | 45010 bypasses the SoC cut-off, the backup reserve, the error mask and the charge and discharge limits, and holds until the control unit restarts: **high risk**. Use `force_mode` with the charge and discharge power set-points instead. 45009: use the backup switch (41200). |
| 46000 | Switches the RS485 port to the shell (`0x5100`, persistent) or starts the OTA mode, which deletes the Modbus TCP, Wi-Fi and cloud tasks and stops the inverter. | **High risk.** It disables RS485 Modbus persistently or takes the network tasks away until the next reboot. Never read or written. |
| 37000 | Read mirror of 41100, the RS485 slave address. | A duplicate: 41100 is already offered. |
| 37001, 37002, 37003 | Calibration state and counters of the micro. | They are non-zero only during and after a 40000 test, which is not offered, so they would always read 0. |
| 45029, 45006, 32114, 30110, 30211 (Venus A) | Pack coding (45029), query of the inverter's hardware-fault input (45006) and their results (32114, 30110, 30211). | Functionless on the Venus A. The pack encode sequencer is compiled out of the control firmware, so 45029 has no reader and 32114 / 30110 only echo the last write; the A micro has no hardware-fault input query, so 30211 holds an undefined byte. They work on the Venus D, where they are offered. |
| 38000–38014 and 30214 (Venus A) | MPPT stage frames (0x40–0x43) and a BMS self-check frame. | The MPPT stage is inside the Venus A micro and nothing sends these frames, so the registers carry nothing. Reading 38000–39014 even makes the control unit broadcast four CAN frames per second until the next reboot. |
| 45023, 45024 (Venus A) | Diagnostic queries of the micro: PE-voltage offset measurement (45023) and current-offset report (45024). | 45023 switches two micro pins and stalls the micro's main loop for about 5000 ADC samples; the reply of 45024 briefly overwrites 30035, 32100, 32101 and 32108 with stale bytes. |
| 45031 (Venus D, Venus A) | BMS restart handshake. | No effect on the BMS side; a write only stalls the Modbus task for about 5 seconds and ends in an exception. |
| 45020–45024 (Venus D) | Commands to the class-2 unit (the MPPT-type unit of the Venus D): switch on with a power value (45020), on/off (45021), registers 0xFB/0xFE/0xFF (45022–45024). | The receiving unit has no firmware that could be checked, so the effect is open. Nothing is offered until it is known; the registers are not in the DEV buttons either. The Venus A offers 45020, 45021 as DEV buttons because there the MPPT stage is the micro itself. |
| 45030 (Venus D) | BMS system command 0x0B/0x0C (master role). | Functionless on the Venus D: the BMS 117.7/118 has no handler for it. The Venus A offers it as a DEV button. |
| Pack 7 (Venus A) | Registers of a seventh battery pack (`battery_7_*`). | The BMS 1105 sends packs 1 to 6 only, so pack 7 always read 0. It will be added again if a BMS version sends it; every new BMS version is checked for that. |
| 45011 (Venus E v3) | Selects the battery profile of the BMS (Modbus value 0 to 9, remapped to the profiles 0 to 5) and stores it permanently in the BMS: the SOC / OCV / SOH model and the charge and discharge current matrices switch. | **High risk.** A wrong profile can give a wrong state of charge and unsuitable charge currents, for example in the cold. The Modbus values map unevenly (1 and 4 both select profile set 0; set 3 can only be reached through the BMS shell), so it is no normal entity. The active profile is shown read-only as `battery_1_profile`. On the Venus D and A the BMS has no receiver for it. |
| 45031 (Venus E v3) | BMS watchdog restart (0x04 reboot, then 0xA0 sleep until the watchdog resets it). | Not offered: the BMS 115 really restarts (its output is off for about 10 to 12 s), but the Modbus reply is mostly exception 3, because the control unit's 5 s window is shorter than the watchdog (about 10 s). The success message is unreliable. |
| 45020–45024 (Venus E v3) | Commands to the class-2 unit (the MPPT-type unit): switch on with a power value (45020), on/off (45021), registers 0xFB/0xFE/0xFF (45022–45024). | Functionless on the Venus E v3: it has no MPPT or class-2 node, and none of the three firmwares can receive or answer such frames. The result registers 30028–30036 and 37017–37024 read 0. |
| 45027, 45029, 45030 (Venus E v3) | BMS master reboot (45027), pack coding (45029), BMS master role (45030). | No effect on the Venus E v3: the BMS 115 has no handler for 0x0A / 0x0B / 0x0C and no pack coding, and the micro 119 drops these frames in its hardware filter. The Venus E v3 has no pack roles. |
| 30010 (Venus E v3) | Work mode of the inverter micro. | Only valid after 45000 (a maintenance state), otherwise stale or 0; 45000 is not offered. The work mode in effect is `user_work_mode`. |
| 41500–41515 (Venus E v3) | The SSID buffer of the communication module (read-back). | Not an entity: it is a RAM buffer that only takes effect through a later password commit. The service [`set_wifi`](set-wifi.md) writes it. The Venus D reads it back as `wifi_ssid`. |
| Packs 2 to 7 (Venus E v3) | Registers of further battery packs (`battery_2_*` to `battery_7_*`, 34100–34699) and a pack counter or online mask (32109–32111). | The Venus E v3 has one fixed pack (stated by the owner; the BMS 115 only ever sends pack 1, with 16 cells). The pack registers 34100–34699 never carry data and always read 0; 32109, 32110 and 32111 are the constants 1, 1 and 1. Every new BMS version is checked for a higher pack capacity. |
| Alias registers | Registers that return the same value as an offered register (aliases onto the same memory location, mirrors, follow-on registers of a multi-part block). | They would only repeat an entity that exists. |
| 41600–41631 | The password buffer of the Wi-Fi credentials. Write-only: it always reads 0. | A password register is not an entity. The registers are written by the service [`set_wifi`](set-wifi.md), which validates everything first and never reads or logs the password. Every further zero register after the terminator would trigger a second takeover, so they must not be written one by one. |
| `max_charge_power`, `max_discharge_power` = 0 | The value 0 for the maximum charge or discharge power. | Never offered; the limits start at 50 W. The inverter stores the value in its EEPROM and reloads it after every restart without a range check, so 0 blocks charging or discharging for good. The register reads 0 after every restart until it is written again, so a forgotten 0 looks like a defective battery, and each write wears the EEPROM. On the Venus E v3 a stored 0 would at least show in the read-back, but it is still persisted by the micro and reloaded without a range check, so the minimum stays 50 W there too. To stop charging or discharging, use `force_mode` = standby or set the power set-point or a schedule slot to 0: those are volatile. |
| Maximum 2500 W (Venus E v3) | Charge and discharge limits above 2500 W. | The firmware accepts 2500 W as input. After a factory reset the inverter micro stands at 3000 W: that reading is shown as it is, but 3000 W can no longer be written back. |
| Maximum 1450 W (Venus A) | Charge and discharge limits and set-points above 1450 W. | The control unit accepts up to 1500 W, but the inverter micro silently drops 1451 W and more: it acknowledges the write and keeps its old limit, so a higher value would only be displayed. 1450 W is the highest value that takes effect. |
